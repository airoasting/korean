# 결제 시스템 이전 프로젝트 회고

# 결과
- 계획보다 3주 늦은 9월 22일에 이전을 마쳤다
- 이전 후 2주 동안 결제 장애는 0건이었다
- 결제 승인 응답 시간은 평균 1.8초에서 0.9초로 줄었다

# 잘한 것
- 전체 트래픽의 5%부터 시작해 단계적으로 전환했다. 문제가 생겨도 영향 범위가 작았다
- 기존 시스템과 새 시스템을 2주간 병행 운영하며 거래 결과를 매일 대조했다
- 운영팀과 CS팀에 전환 일정을 미리 공유해 고객 문의에 빠르게 대응할 수 있었다

# 아쉬운 것
- 지연의 주된 원인은 정산 데이터 형식 차이였다. 설계 단계에서 정산팀과 검토하지 않았다
- 테스트 환경의 데이터가 실제와 달라 일부 예외 케이스를 운영 직전에야 발견했다
- 일정이 밀리는 동안 이해관계자에게 상황을 늦게 알렸다

# 다음에 바꿀 것
- 데이터를 다루는 프로젝트는 설계 리뷰에 데이터를 쓰는 팀을 반드시 포함한다
- 운영 데이터를 익명화한 테스트 세트를 프로젝트 초기에 만든다
- 일정이 1주 이상 밀릴 조짐이 보이면 그 주에 바로 공유한다
